# Correction Ledger

Status: public correction ledger (entries C-01..C-25, current through v0.35.0 — the chapters 57-61 arc's pre-release corrections are scored inside the chapters themselves per the draft-stage policy). The C-19..C-24 block records the pre-publication adversarial panel's corrections to the chapters 53-56 arc, printed alongside the results they correct; draft-stage corrections remain scored inside their own chapters (e.g. chapter 49 §12).

The correction ledger is part of the method. It records claims that were killed,
demoted, narrowed, or moved to a hold. A failed claim may leave a useful
residue, but the old headline must not survive under softer wording.

## Rule

Every correction should preserve:

1. the original or tempting statement;
2. what survived;
3. the current public status;
4. the condition under which the issue may be reopened.

## Reopening Protocol

To reopen a killed or bounded claim:

1. State the old failure.
2. Name the new projection, admission data, or interface.
3. Pre-register matched controls.
4. Define the success statistic.
5. Define the kill condition.
6. Run the smallest decisive audit first.
7. Promote only the scoped residue, not the old headline.
